# 长文浓缩成一页纸（编排者）

## 这不是"写摘要"，而是做信息取舍

**第一目标：让读者最快看懂、用最少记忆量带走关键结论。** 压缩只是手段；页数是结果，不是目标。当"再删一点"会让读者看不懂或必须额外记忆时，**保留内容并升页**，而不是为了守住页数把结构压断。

保留能改变回答或决策的内容，删掉铺垫、重复和可由常识推导的内容。判断标准是"考场或工作中会不会用到"，不是"原文重不重要"。

本 skill 是**编排者**：自己负责选点、取舍、压缩与图片分流；把两件已有专门技能的事委托出去——

| 环节 | 执行方 | 为什么不自己做 |
|---|---|---|
| 选点、压缩、内容取舍、图片分流 | **本 skill** | 这是本 skill 的核心，不可委托 |
| 版本时效核实（第 8 步） | `fact-freshness-check` 子技能 | 联网取证有独立规则与四态判定 |
| 排版渲染与结构校验（第 9–10 步） | `onepager-render` 子技能 | 版式/分页/字号/图片内嵌/打印实测有独立规则与脚本 |

**流程顺序与交付形态不变**——只是执行方换成了子技能。子技能不可用时按本 SKILL 的降级路径处理，不静默失败。

## 边界清单

输入：一份单文档（Markdown、TXT、HTML、PDF、DOCX 提取后的文本，**可含原文图片**），通常 3–50 页。
输出：**一个单文件 HTML**，1–3 页 A4（默认 1–2 页，满足突破条件可到 3 页），打印样式已内置。用户自己用浏览器打印，不生成 PDF/DOCX，除非明确要求。

| 能做 | 不做 |
|---|---|
| 单文档 → 1–3 页 A4 HTML；保留关键数字、条件、话术、**必要图片** | 多文档聚合（→ `knowledge-router` / `docs-to-knowledge`）；4 页以上；PDF/DOCX；交互页 |
| 选点评分、压缩阶梯、骨架保护、编辑质量门、**原文图片分流**（重绘 / 内嵌 / 删除） | 版式细节与打印实测（→ `onepager-render`） |
| 为"看懂优先"弹性升页，并给出升页理由 | 版本核实本身（→ `fact-freshness-check`）；纯图集/纯音视频无文字 |
| 无版本敏感断言时标注"未联网校验" | 虚构原文没有的数字、结论、因果、图注 |

## 路由元信息

| 项 | 内容 |
|---|---|
| 正向触发 | 压成一页/两页、浓缩、提炼要点、一页纸、面试要点、复习提纲、cheat sheet |
| 反向不触发 | 多文档/目录/知识图谱 → `docs-to-knowledge`；**需要 4 页以上 → `docs-to-knowledge`**；只校验 → `fact-freshness-check`；只要排版 → `onepager-render` |
| 禁用场景 | 源文不足 1 页且未要求压缩；需要保留大量细节；纯图集/纯音视频无文字 |
| 优先级 | 用户指定页数 > `knowledge-router` 路由 > 本 skill 默认 |

**与 `docs-to-knowledge` 的分界（硬规则）**：本 skill 产出 **≤3 页**；**≥4 页转 `docs-to-knowledge`**。越过 3 页说明信息量或图片载荷已超出速查件定位，不要硬压也不要无限升页。

## 硬约束（内容侧预算）

以下预算是**内容取舍的依据**，由本 skill 保证；页面结构层面的达标由 `onepager-render` 校验。

| 项目 | 1 页 | 2 页 | 3 页（突破档） |
|---|---|---|---|
| 正文中文字符 | 600–800 | 1200–1600 | 1800–2400 |
| 一级标题 | 1 个 | 1 个 | 1 个 |
| 核心要点 | 3–5 条 | 6–10 条 | 10–14 条 |
| 图（SVG＋内嵌原图） | 0–1 个 | 1–2 个 | 2–4 个 |
| 表 | 0–1 个 | 0–2 个 | 0–3 个 |
| 图节点数 | ≤8 | ≤12 | ≤12 |
| 最小字号 | 9pt | 9pt | 9pt |
| 每页最低密度 | — | — | ≥400 中文字或等效图表 |

超过预算时**先判断"删了会不会看不懂"**：会 → 按下方突破规则升页；不会 → 按「压缩阶梯」删。禁止缩小字号或压缩行距来硬塞（后者由 `onepager-render` 拒绝执行）。3 页档的"每页最低密度"是防凑页门槛：达不到说明该回 2 页。

**页数由选点结果驱动，不由源文长度驱动**（用户指定页数时仍以用户为准）：完成「打分选点」后按高分 KU（总分 ≥5）数量定档——≤7 个 → 1 页；8–12 个 → 2 页；13–16 个且满足突破条件 → 3 页；>16 个或突破条件给不出 → 停下报告，转 `docs-to-knowledge` 或与用户确认取舍。源文长度只作初筛：源文 ≤3 页且高分 KU ≤7 才默认 1 页；"源文短"不等于"信息少"——短而密的方法论/清单/话术类源文常落在 2 页档。禁止先用模板上限（如"要点 3–5 条"）反削源文结构：页数档位不够装下全部高分 KU 时升页，不删骨架。

## 页数突破规则（看懂优先）

默认 1–2 页；**升到 3 页必须至少满足一条，并在交付报告写明是哪一条**：

1. **结构断裂**：删掉某条要点或某张图，会让因果链、流程链或对比关系断掉，读者需要自行补猜。
2. **图片载荷**：有 ≥2 张必保留图片（见「原文图片分流」），1–2 页版面放不下，且删图会丢关键信息。
3. **记忆量上升**：两页内合并要点会迫使读者额外记住前提（例如把五个并列维度压成"五维度见上"），违背"最少记忆量"。

**不许升页的情况**：内容只是"多"，删掉铺垫、重复、无结论例子后不影响看懂——按压缩阶梯删，不升页。**也不是升页就能解决**：如果 3 页仍装不下，或高分 KU >16，转 `docs-to-knowledge`，不要做 4 页。

**骨架内容受保护**：同级枚举（如"五大支柱"）、决策链（如"错误分级→处置通道"）、可背诵话术（如答题顺序）是高分 KU 的常见形态。压缩阶梯只允许删低分 KU 与同义冗余表达；骨架的删减/合并必须显式记录到交付报告，不允许静默丢弃（例如五大支柱只留四个标签、第五支柱整个消失）。

**分页填充规则**：不在本 skill 展开——第 8 步交给 `onepager-render`，由其按"顺序填满一页、溢出单位整体下移、末页允许不满"执行；本 skill 只决定页数档位与内容归属。

**时效备注**（见第 7 步）：形态 A 紧凑区块 ≤4 条 / 约 200 字符，或形态 B 附录页 ≤12 条。不计入正文字符预算，契约见 `references/freshness-rules.md`。

**术语附录页**：中英文术语解释放文末 `<section class="page page--glossary">`，≤12 行三列表（术语 / 全称或中文 / 一句话解释），只收正文实际出现的缩写与专有框架名，按首次出现顺序排列。与时效附录页一样**不计入 1–3 页知识点预算**（checker 豁免并单独统计），最多 1 页。

## 原文图片分流（混合策略）

线上文章常用图片承载结构（架构图、流程图、对比图）或证据（后台截图、报表、作品图）。**只取文字会让这些段落结构断裂**——读者看到"如上图所示"却无图，整段不知所云。因此图片按类型分流，不搞"全部丢弃"也不搞"全部照搬"：

| 图片类型 | 判定信号 | 处理方式 |
|---|---|---|
| 结构/机制/流程示意图 | 能用节点＋连线/层级表达；原文靠它讲"怎么运作" | **重绘为内联 SVG**：可简化布局，不改逻辑、数字与方向 |
| 界面截图、真实数据图表、实物/作品图 | 像素细节本身是信息（UI 长什么样、报表长什么样） | **原图 base64 内嵌**，必须带 alt 与图注 |
| 装饰图、头像、logo、花纹、封面 | 删掉后读者不需要补充任何信息 | **删除** |
| 无法判断 | — | 保守保留（内嵌）并标注"来源原图" |

**图片准入测试**：删掉这张图，读者是否需要额外记忆或猜测？需要 → 保留；不需要 → 删。**宁可多留一张有信息量的图，也不要为守页数把结构删断。**

**保留图的三条硬要求**：

1. 每张保留图必须有图注，写"这张图回答什么问题"，不写"图 1""如上图"。
2. 原图内嵌为 base64（`<img src="data:image/...;base64,..." alt="...">`）：单图 ≤400KB、总计 ≤2MB；超出先降采样（长边 1600px、JPEG q85）。
3. 灰度打印可读：截图里的彩色高亮/标记必须配文字说明，不能只靠颜色区分。

**采集方式**：取图片原始 URL（不是页面缩略图），下载后转 base64。下载失败时改为**图注文字化**——用一段话描述图中关键信息，并标明"原图未随附"，**不得凭空补画或编造图中数据**。

**与自绘 SVG 的分工**：自绘 SVG 只画"关系"（流程/分支/状态/层级）；原图内嵌只用于"像素即信息"（界面/数据/实物）。两者都不占的图删掉。

## 工作流（十步，第 8–10 步委托子技能）

1. **提取与锚定**（本 skill）：读入全文，按小节或段落编号（P1、P2…）。PDF/DOCX 先转文本；保留标题层级。**图片在原文位置就地标记**（`[IMG-1 @P3: 架构图, alt=...]`），先不判断去留。多个文件先合并去重。
2. **图片清点与分流**（本 skill）：按「原文图片分流」给每张图定去留——重绘 SVG / 原图内嵌 / 删除 / 待定；记录到 `.skill-state/`，并把"图注要回答什么"一起写下。此后选点与压缩都以"图＋文"为整体单位，不拆散。
3. **原子化**（本 skill）：把原文拆成"知识单元"（KU）。一个 KU = 一个可独立成条的结论、机制、对比或边界条件。不要以段落为单位。同级枚举（N 个支柱/步骤/维度）按项拆，一项一个 KU，不把整组压成一个标签 KU。**依赖某张图的 KU，把该图作为 KU 的一部分计入。**
4. **打分选点**（本 skill）：按下方评分表给每个 KU 打 0–2 分，保留总分 ≥5 的；再补上被引用但未入选的前置概念。1 页最多 7 个 KU，2 页最多 12 个，3 页最多 16 个。**打分结果先落地再继续**：把 KU 清单（内容 / 分数 / 去留 / 关联图片）写入 `.skill-state/<中文任务名>.md`，未落地不许进入成稿步骤——没打分就写正文，等于跳过取舍。
5. **结构化成稿**（本 skill）：按 interview 或 knowledge 模板填入；先写一句话答案，再写要点，最后配图或表。**断言完整性检验**：逐条核对保留要点是否为"结论＋条件/机制"的完整句；关键词堆叠（如只写"三层规划"而不含"里程碑定死、执行层自适应"）＝压缩事故，必须展开或回退重选。
6. **编辑契约**（本 skill，强制）：填「章节契约 + 术语表」，跑 MECE 测试；定义/定位只能放开头，流程/评测/迭代节只收动作与指标。详见 `references/editorial-qa.md`。
7. **压缩到预算**（本 skill）：用压缩阶梯逐级删，直到字符数、要点数、图数进入本 SKILL「硬约束」表的目标区间；**压缩时先删无图支撑的铺垫，再动有图支撑的结构**。
8. **时效校验 → 调用 `fact-freshness-check` 子技能**（必选，用户明确说"不用校验"才跳过；由 `knowledge-router` 调用时同样强制）：提取版本敏感断言（默认值、限制、性能结论、支持范围、已废弃特性），按该子技能的流程对照官方当前版文档核实。**正文只写当前版本的事实**：[演进] 的条目必须先回写正文，把结论改成当前版本的行为，再把旧版行为与起始版本写进时效区块；[表述不完整] 的补上限定词；[未核实] 的正文加"待核实"标记并进区块。时效区块是演进脉络与深度展示，**不是知识纠正环节**。区块条目格式按 `references/freshness-rules.md`。输入为项目自述/私人笔记且无外部技术断言时，可不联网，但需在交付报告写明"无版本敏感断言，未联网校验"。不得虚构。
9. **渲染 HTML → 调用 `onepager-render` 子技能**：把定型内容（标题、一句话答案、要点、图表与图片清单、边界、话术、页数档位、时效条目）交给它；由它复制模板、替换占位、按分页填充规则落页、绘制 SVG 骨架、内嵌原图、插入时效/术语附录页。本 skill 不再维护模板与版式规则。
10. **自检 → 调用 `onepager-render` 的校验 + 本 skill 冷读者复审**：运行 `<onepager-render>/scripts/check_onepager.py <file.html>`（FAIL 必修、WARN 必解释），再按 `references/editorial-qa.md` 做冷读者复审并写出交付报告。结构类问题回给子技能修，内容类问题回第 4 步重选。

## 选点评分

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 必答性 | 与主题无关 | 相关但非核心 | 直接回答主题 |
| 区分度 | 谁都知道 | 知道更好 | 答不出就露怯 |
| 可迁移性 | 只适用于本例 | 偶尔复用 | 可用于追问或同类题 |
| 不可推导性 | 常识可推 | 半推导 | 必须记住的事实、数字或条件 |

**不可推导性判据**：以"考场/工作现场能否推出来"为准。可直接背诵的分级处置链（什么错误走什么通道）、答题话术与顺序、默认值/阈值、具体机制分工（A 管什么 B 管什么）都按 2 分计——"听起来有道理"不等于"能现场推出"，恰恰是最不该删的背诵型得分点。

优先保留：定义、因果机制、数量级、边界条件、对比维度、常见误区。
优先删除：历史背景、作者经历、无结论的举例、重复结论、营销性描述、"随着…的发展"式铺垫。

## 压缩阶梯

按顺序执行，达到预算即停：

1. 删铺垫：背景、动机、行业趋势、与结论无关的例子。
2. 合并同义：同一结论出现多次只留最准确的一次。
3. 段落变要点：每条 ≤25 字，动词或名词开头，去掉"首先/其次/此外/总之"。
4. 并列 ≥3 项改成表格；有先后、分支、状态或层级才改成图。
5. 长解释改成"结论 + 适用条件"一句话，把解释留给口头表达。
6. 仍超：先升页（1→2；仅在满足「页数突破规则」时 2→3）再删"追问"→ 删"易错点"→ 换更小的图；**同级枚举对称**——要么等深度全保留，要么整组合并进上层条目并在交付报告显式说明，不允许只留标签词或砍掉第 N 项。
7. 绝不做：缩到 8pt、压行距、删到只剩标题、把内容藏进 `<details>`；删骨架 KU 凑页数。

## 两种结构

### interview（默认用于面试题、面经、八股）

```text
H1 题目（≤20 字）
一句话答案（≤40 字，结论先行）
核心要点 3–5 条（每条 ≤25 字；2 页版 6–10 条）
图或表 1 个
易错点/边界 2–3 条
追问 2–3 条（仅 2 页版）
```

"要点 3–5 条"是 1 页档上限，不是固定配额：高分 KU 多于 5 个时先升 2 页（上限 10 条），不允许为守 5 条把第 6 个支柱削成标签。

### knowledge（默认用于技术文档、课程、文章）

```text
H1 主题
一句话定义（≤40 字）
为什么存在 / 解决什么问题 1–2 条
关键机制 3–5 条
图或表 1 个
边界与误区 2–3 条
记忆锚 1 条（可选）
```

写作要求：

- 每一条都能独立读懂，不依赖上下文。
- 数字、条件、限定词必须保留（"通常""仅当""在 X 场景下"）。
- **正文只陈述当前版本的事实**。历史版本的行为（"5.7 及以前是 X"）不进正文，写入时效区块作为演进脉络——读者先得到今天的正确答案，再从区块获得深度。
- 不写"本文介绍了…""综上所述"这类元话语。
- 一句话答案必须是可背诵的完整句子，不是关键词堆。

## 图示与版式（委托 `onepager-render`）

第 9–10 步的图示选择、SVG 约定、原图内嵌、字号、分页、附录页插入位置、打印实测，全部由 `onepager-render` 负责，规则见该技能的 `references/diagram-playbook.md` 与 `references/html-spec.md`。

本 skill 只需在交接时说明四件事：**这张图要回答什么关系**（流程/分支/状态/层级才画，同维度对比用表格）、**哪几张是原图内嵌及图注内容**、**它在 1/2/3 页档下的节点与图数上限**、**哪些是时效/术语附录条目**。

## 编辑契约（防空话错位/命名撞车）

写正文前必须填两张表：

1. **章节契约**：章节 / 这一节回答的问题 / 只收 / 不收。定义和定位只能进开头；流程、评测、迭代节只收动作、指标与回流。
2. **术语表**：术语 / 管什么 / 不管什么 / 易混词。两个标题共享同一个未限定关键词（如都含"输出"）即视为撞车，必须加限定词（内容/呈现/验收/执行）或合并。

**MECE 测试**：同一段内容能否同时放进两个模块？能 → 边界没写清，先改名字或补"不管什么"，不要靠读者猜。

**语病与杂质扫描（成稿后强制，防"生成时语病"类事故）**：把 HTML 去标签后通读一遍纯文本，按以下条件检查——发现任何一条即修正，不允许带病交付：
1. **中英夹杂异常**：正文中文句子里突然冒出无关英文词、生造混合词（如"自 fit""register"当动词）;技术名词白名单之外,中文句子中不得插入单个英文裸词。
2. **半截句/残缺词**：句号前后语义断裂、主谓宾缺失、"看起来像中间被截断"的词（半普通话半术语拼接）。
3. **Markdown/HTML 符号残留**：HTML 里出现 ``**``、`##`、未转义的 `&`、孤立的反引号——尤其 `<li>`/表格里直接写了 Markdown 语法（不会渲染、只会显示星号）。
4. **标签残缺**：`<tdxxx>` 这类畸形标签、未闭合的 <strong>/<code>（用带语法高亮的编辑器或简单正则自检）。
5. **人造词检查**：把可疑词放到"中文读者第一眼能否读懂"的试金石上——读不懂就改写成正常中文。

成因多为长文生成时的 token 拼接事故，**写时无法完全预防，只能靠这一道收尾扫描兜底**；修补类编辑（事后追加）同样适用于此扫描。若模型对长文易发语病，优先把长段落改写为要点列表（列表结构天然更稳）。

写完后做**冷读者复审**：只读标题和每块首句，回答"这句话在回答这个标题吗""只看标题能分清这两节吗"。清单不为空就返回修改。完整规则与示例见 `references/editorial-qa.md`。

## 自检清单

内容侧（本 skill 负责）：

- [ ] 一句话答案 ≤40 字，且是完整句子。
- [ ] 每条要点 ≤25 字，删掉连接词。
- [ ] 每个数字或结论都能在原文找到依据；不确定的标"待核实"。
- [ ] 归属：每块首句回答本节问题；定义/定位在开头，不在流程/评测/迭代节。
- [ ] 命名：只看标题能说出任意两节区别；两个标题不共享未限定关键词（checker 会 WARN）。
- [ ] 回放测试：盖住原文只读成品，能把源文骨架完整讲一遍（同级枚举不缺项、决策链不断链）；做不到＝删过头，回退重选。
- [ ] 断言完整：保留要点均为"结论＋条件/机制"完整句，无关键词堆叠。
- [ ] 同级对称：同级枚举要么等深度全保留，要么整组合并并已在报告说明。
- [ ] 语病与杂质扫描已通过：无中英夹杂异常、无半截句、无 Markdown/HTML 符号残留、无畸形标签（含修补类追加后）。
- [ ] 页数档位由高分 KU 数驱动；KU 清单已落地到 `.skill-state/`。
- [ ] **页数为 3 时，交付报告写明了突破理由**（结构断裂 / 图片载荷 / 记忆量），且每页达到最低密度。
- [ ] **图片已逐张分流并留痕**：重绘 SVG / 原图内嵌 / 删除；保留图均有"回答什么问题"的图注。
- [ ] **没有出现"如上图所示"却无图的断言**：依赖图的要点要么带图，要么改写为自解释文字。
- [ ] **图注与图中数据均有原文依据**，无编造坐标、数值、界面元素。
- [ ] 输出文件名使用中文（`浓缩-<中文主题>.html`），无英文 slug、拼音或日期缩写。
- [ ] 版本敏感断言已过时效校验（子技能）；正文不含已被新版本推翻的结论——[演进] 条目的当前行为已写入正文，区块只承载演进脉络。
- [ ] 时效区块首行含"截至 <产品> <版本> · <日期> 核实"；每条带出处。
- [ ] 术语附录（如有）：只收正文出现过的缩写/框架名，≤12 行，按首次出现顺序，不重复正文定义句。

结构侧（`onepager-render` 负责，本 skill 只核对其结果）：

- [ ] 页数 = 1 或 2，`.page` 数量正确。
- [ ] 每页中文字符在预算内（check 脚本）。
- [ ] 图 ≤8 或 ≤12 节点，黑白可读，无外部依赖。
- [ ] 最小字号 ≥9pt，无标题孤行。
- [ ] 页脚可见；若仅页脚轻微溢出，已删除页脚并注明「页脚省略」。
- [ ] 视觉验收：支持图像输入时已过目；不支持时已在报告提醒用户自行过目。
- [ ] 浏览器 Ctrl+P 预览：无空白页、无截断、无内容溢出。

## 交付

写文件到当前目录：`浓缩-<中文主题>.html`（或用户指定路径）。文件名使用中文：主题用 2–12 个中文字概括，不用英文 slug、拼音或日期缩写；用户指定路径时以用户为准，但文件名仍建议中文。

聊天里只报告：

- 页数、每页字符数、图/表数量
- **页数突破理由**：3 页时必须写明属于哪一条（结构断裂 / 图片载荷 / 记忆量）；因图片升页的 2 页档也要说明
- **图片处理清单**：原图 N 张 → 重绘 SVG a 张 / 原图内嵌 b 张 / 删除 c 张；若删除的是论证支柱，单独点名
- 高分 KU 数量与页数档位的对应（档位由选点驱动）
- 保留的 KU 数与删除的 KU 数
- 骨架删减说明：同级枚举合并/砍项的，逐条列出（无则写"骨架完整保留"）
- 视觉验收状态：已做 / **放弃（模型不支持图像输入，建议用户打印时自行过目）**
- 时效校验结果（来自子技能）：核实 N 条，四态分布；逐条列出 [演进]（正文已按当前版改写 + 区块记演进路径）和 [未核实]
- 子技能执行状态：`fact-freshness-check` 与 `onepager-render` 是否已执行／走了降级路径
- 因预算删除但可能重要的 1–3 条
- 是否使用了"待核实"标记

不要把整份 HTML 贴进聊天。

## 异常与兜底

| 场景 | 处理 |
|---|---|
| 源文不足 1 页 | 不硬凑，输出 1 页并说明「信息量不足以支撑 2 页」 |
| 扫描版 PDF 无文本 | 先 OCR；不可用则停止并告知，不凭空补内容 |
| 超出页数/字数预算 | 按压缩阶梯删；禁止缩小字号或压缩行距 |
| 高分 KU > 12 个 | 不硬压；停下报告，建议转 `docs-to-knowledge` 或与用户确认取舍 |
| 多文档输入 | 停止并转 `knowledge-router` / `docs-to-knowledge` |
| 校验失败或无证据 | 正文标「待核实」，报告逐条列出 |
| 正文/图表溢出 | 交 `onepager-render`：删卡/合并要点后重跑 check；仍溢出则升页或减图 |
| 仅页脚轻微溢出 | 由 `onepager-render` 删除页脚，不升页、不缩字号；报告注明「页脚省略」 |
| 子技能不可用 | 按「依赖与资源」表的降级路径执行，并在报告显式注明；不静默跳过 |
| 原文图片下载失败 | 改为图注文字化并标"原图未随附"；不凭空补画、不编造图中数据 |
| 单图过大 / 总体积超 2MB | 降采样（长边 1600px、JPEG q85）；仍超则只留关键裁切并说明 |
| 图片类型无法判断 | 保守保留（内嵌）并标注"来源原图"，在报告里列出待确认 |
| 3 页仍装不下 | 不许做 4 页：转 `docs-to-knowledge`，或与用户确认删减范围 |
| 模型不支持图像输入 | 放弃视觉验收，不反复重试读图/视觉代理；报告提醒「未做视觉验收，建议用户打印时自行过目」；结构验收照常执行 |
| 多来源冲突 | 以最新/最权威为准并在页脚注明；无法判断时并列 |

## 状态与权限

- 多轮状态：`.skill-state/<中文任务名>.md`，字段：输入 / KU 清单（内容+分数+去留） / 页数档位 / 已删项（含骨架删减记录） / 剩余预算 / 子技能执行状态。
- 高风险操作需二次确认：覆盖已有 HTML、删除文件、安装 npm 包、写到用户指定目录之外。
- 不修改原始输入文件。
- 子技能由本 skill 编排调用；用户可单独调用任一子技能（`onepager-render` 排版、`fact-freshness-check` 校验），此时本 SKILL 的预算与结构约定只在外层流程生效。

## 反模式

| 不要 | 要 |
|---|---|
| 每段各压一句，结果还是三页 | 先选点，再写 |
| 用"首先/其次/总之"串联 | 直接给结论和条件 |
| 为凑页数加空话 | 加一张对比表或边界条件 |
| 先定页数再削源文结构凑条数 | 页数跟着高分 KU 数走，不够就升页 |
| 同级枚举压成标签词、砍掉第 N 项 | 等深度全保留，或整组合并并显式报告 |
| 跳过打分直接套模板 | KU 清单落地后再成稿 |
| 在编排层重写版式规则 | 版式一律引用 `onepager-render`，避免两份规则漂移 |
| 子技能不可用时静默降级 | 走明示的降级路径并在报告注明 |
| 为守页数删掉论证关键的图 | 图承载结构就保留；装不下按突破规则升 3 页 |
| 把界面截图"重绘"成示意图 | 像素即信息的图必须原图内嵌，重绘＝二次失真 |
| 图注写"图 1""如上图所示" | 写"这张图回答什么问题"，让图自带信息 |
| 所有知识都画图 | 只有流程、分支、层级才画 |
| 缩小字号硬塞 | 按阶梯删内容 |
| 正文先写过时结论、靠时效区块纠正 | 正文直接写当前版本，区块记演进 |
| 依赖 Mermaid CDN | 内联 SVG |
| 把内容折叠进 `<details>` | 打印时会被丢掉 |
