# 长文浓缩成一页纸

## 边界清单

输入：一份单文档（Markdown、TXT、HTML、PDF、DOCX 提取后的文本），通常 3–50 页。
输出：**一个单文件 HTML**，固定 1 页或 2 页 A4，打印样式已内置。用户自己用浏览器打印，不生成 PDF/DOCX，除非明确要求。

这不是"写摘要"，而是**做信息取舍**：保留能改变回答或决策的内容，删掉铺垫、重复和可由常识推导的内容。判断标准是"考场或工作中会不会用到"，不是"原文重不重要"。

| 能做 | 不做 |
|---|---|
| 单文档 → 1–2 页 A4 HTML；保留关键数字、条件、话术；配 1–2 张机制图 | 多文档聚合（→ `knowledge-router` / `docs-to-knowledge`）；3 页以上；PDF/DOCX；交互页 |
| 无版本敏感断言时标注"未联网校验" | 版本校验本身（→ `fact-freshness-check`）；图像理解超出 OCR 范围 |
| 按预算删减并报告删了什么 | 虚构原文没有的数字、结论、因果 |

## 路由元信息

| 项 | 内容 |
|---|---|
| 正向触发 | 压成一页/两页、浓缩、提炼要点、一页纸、面试要点、复习提纲、cheat sheet |
| 反向不触发 | 多文档/目录/知识图谱 → `docs-to-knowledge`；只校验 → `fact-freshness-check`；要 3 页以上 → `docs-to-knowledge` |
| 禁用场景 | 源文不足 1 页且未要求压缩；需要保留大量细节；多文档；图片/音视频 |
| 优先级 | 用户指定页数 > `knowledge-router` 路由 > 本 skill 默认 |

## 硬约束

| 项目 | 1 页 | 2 页 |
|---|---|---|
| 正文中文字符 | 600–800 | 1200–1600 |
| 一级标题 | 1 个 | 1 个 |
| 核心要点 | 3–5 条 | 6–10 条 |
| 图 | 0–1 个 | 1–2 个 |
| 表 | 0–1 个 | 0–2 个 |
| 图节点数 | ≤ 8 | ≤ 12 |
| 最小字号 | 9pt | 9pt |

超过预算时按「压缩阶梯」删，禁止缩小字号或压缩行距来硬塞。

**页数由选点结果驱动，不由源文长度驱动**（用户指定页数时仍以用户为准）：完成「打分选点」后按高分 KU（总分 ≥5）数量定档——≤7 个 → 1 页；8–12 个 → 2 页；>12 个 → 停下报告信息密度超预算，建议转 `docs-to-knowledge` 或与用户确认取舍。源文长度只作初筛：源文 ≤3 页且高分 KU ≤7 才默认 1 页；"源文短"不等于"信息少"——短而密的方法论/清单/话术类源文常落在 2 页档。禁止先用模板上限（如"要点 3–5 条"）反削源文结构：页数档位不够装下全部高分 KU 时升页，不删骨架。

**骨架内容受保护**：同级枚举（如"五大支柱"）、决策链（如"错误分级→处置通道"）、可背诵话术（如答题顺序）是高分 KU 的常见形态。压缩阶梯只允许删低分 KU 与同义冗余表达；骨架的删减/合并必须显式记录到交付报告，不允许静默丢弃（例如五大支柱只留四个标签、第五支柱整个消失）。

**时效备注**（见下文第 6 步）：形态 A 紧凑区块 ≤4 条 / 约 200 字符，或形态 B 附录页 ≤12 条。不计入正文字符预算，契约见 `references/freshness-rules.md`。

## 工作流

1. **提取与锚定**：读入全文，按小节或段落编号（P1、P2…）。PDF/DOCX 先转文本；保留标题层级。多个文件先合并去重。
2. **原子化**：把原文拆成"知识单元"（KU）。一个 KU = 一个可独立成条的结论、机制、对比或边界条件。不要以段落为单位。同级枚举（N 个支柱/步骤/维度）按项拆，一项一个 KU，不把整组压成一个标签 KU。
3. **打分选点**：按下方评分表给每个 KU 打 0–2 分，保留总分 ≥5 的；再补上被引用但未入选的前置概念。1 页最多 7 个 KU，2 页最多 12 个。**打分结果先落地再继续**：把 KU 清单（内容 / 分数 / 去留）写入 `.skill-state/<中文任务名>.md`，未落地不许进入成稿步骤——没打分就写正文，等于跳过取舍。
4. **结构化成稿**：按 interview 或 knowledge 模板填入；先写一句话答案，再写要点，最后配图或表。**断言完整性检验**：逐条核对保留要点是否为"结论＋条件/机制"的完整句；关键词堆叠（如只写"三层规划"而不含"里程碑定死、执行层自适应"）＝压缩事故，必须展开或回退重选。
5. **编辑契约（强制）**：填「章节契约 + 术语表」，跑 MECE 测试；定义/定位只能放开头，流程/评测/迭代节只收动作与指标。详见 `references/editorial-qa.md`。
6. **压缩到预算**：用压缩阶梯逐级删，直到字符数和图数进入预算。
7. **时效校验（必选，用户明确说"不用校验"才跳过；由 knowledge-router 调用时同样强制）**：提取版本敏感断言（默认值、限制、性能结论、支持范围、已废弃特性），按 `fact-freshness-check` skill 的流程对照官方当前版文档核实。**正文只写当前版本的事实**：[演进]（原"已变化"）的条目必须先回写正文，把结论改成当前版本的行为，再把旧版行为与起始版本写进时效区块；[表述不完整] 的补上限定词；[未核实] 的正文加"待核实"标记并进区块。时效区块是演进脉络与深度展示，**不是知识纠正环节**。格式按 `references/freshness-rules.md`。输入为项目自述/私人笔记且无外部技术断言时，可不联网，但需在交付报告写明"无版本敏感断言，未联网校验"。不得虚构。
8. **渲染 HTML**：复制 `assets/onepager.html`，替换占位内容；图用内联 SVG。
9. **自检**：运行 `python scripts/check_onepager.py <file.html>`，再人工过一遍清单；最后按 `references/editorial-qa.md` 做冷读者复审。

## 编辑契约（防空话错位/命名撞车）

写正文前必须填两张表：

1. **章节契约**：章节 / 这一节回答的问题 / 只收 / 不收。定义和定位只能进开头；流程、评测、迭代节只收动作、指标与回流。
2. **术语表**：术语 / 管什么 / 不管什么 / 易混词。两个标题共享同一个未限定关键词（如都含“输出”）即视为撞车，必须加限定词（内容/呈现/验收/执行）或合并。

**MECE 测试**：同一段内容能否同时放进两个模块？能 → 边界没写清，先改名字或补“不管什么”，不要靠读者猜。

写完后做**冷读者复审**：只读标题和每块首句，回答“这句话在回答这个标题吗”“只看标题能分清这两节吗”。清单不为空就返回修改。完整规则与示例见 `references/editorial-qa.md`。

## 选点评分

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 必答性 | 与主题无关 | 相关但非核心 | 直接回答主题 |
| 区分度 | 谁都知道 | 知道更好 | 答不出就露怯 |
| 可迁移性 | 只适用于本例 | 偶尔复用 | 可用于追问或同类题 |
| 不可推导性 | 常识可推 | 半推导 | 必须记住的事实、数字或条件 |

**不可推导性判据**：以"考场/工作现场能否推出来"为准。可直接背诵的分级处置链（什么错误走什么通道）、答题话术与顺序、默认值/阈值、具体机制分工（A 管什么 B 管什么）都按 2 分计——"听起来有道理"不等于"能现场推出"，恰恰是最不该删的背诵型得分点。

优先保留：定义、因果机制、数量级、边界条件、对比维度、常见误区。
优先删除：历史背景、作者经历、无结论的举例、重复结论、营销性描述、"随着…的发展"式铺垫。

## 压缩阶梯

按顺序执行，达到预算即停：

1. 删铺垫：背景、动机、行业趋势、与结论无关的例子。
2. 合并同义：同一结论出现多次只留最准确的一次。
3. 段落变要点：每条 ≤25 字，动词或名词开头，去掉"首先/其次/此外/总之"。
4. 并列 ≥3 项改成表格；有先后、分支、状态或层级才改成图。
5. 长解释改成"结论 + 适用条件"一句话，把解释留给口头表达。
6. 仍超：先升页（1→2）再删"追问"→ 删"易错点"→ 换更小的图；**同级枚举对称**——要么等深度全保留，要么整组合并进上层条目并在交付报告显式说明，不允许只留标签词或砍掉第 N 项。
7. 绝不做：缩到 8pt、压行距、删到只剩标题、把内容藏进 `<details>`；删骨架 KU 凑页数。

## 两种结构

### interview（默认用于面试题、面经、八股）

```text
H1 题目（≤20 字）
一句话答案（≤40 字，结论先行）
核心要点 3–5 条（每条 ≤25 字；2 页版 6–10 条）
图或表 1 个
易错点/边界 2–3 条
追问 2–3 条（仅 2 页版）
```

"要点 3–5 条"是 1 页档上限，不是固定配额：高分 KU 多于 5 个时先升 2 页（上限 10 条），不允许为守 5 条把第 6 个支柱削成标签。

### knowledge（默认用于技术文档、课程、文章）

```text
H1 主题
一句话定义（≤40 字）
为什么存在 / 解决什么问题 1–2 条
关键机制 3–5 条
图或表 1 个
边界与误区 2–3 条
记忆锚 1 条（可选）
```

写作要求：

- 每一条都能独立读懂，不依赖上下文。
- 数字、条件、限定词必须保留（"通常""仅当""在 X 场景下"）。
- **正文只陈述当前版本的事实**。历史版本的行为（"5.7 及以前是 X"）不进正文，写入时效区块作为演进脉络——读者先得到今天的正确答案，再从区块获得深度。
- 不写"本文介绍了…""综上所述"这类元话语。
- 一句话答案必须是可背诵的完整句子，不是关键词堆。

## 图示

只画三类关系：**流程/时序**、**分支/状态**、**层级/结构**。三者都不占的，用表格，不要硬画。

- 图必须承载信息，不能只是装饰；删掉图后如果信息没损失，就删图。
- 一张图只表达一个关系；节点 ≤8（1 页）或 ≤12（2 页）。
- 用内联 SVG，不用外部图片；不要依赖 CDN 上的 Mermaid JS，离线打印会白屏。
- 需要 Mermaid 时，先生成 `.mmd`，用 `npx -y @mermaid-js/mermaid-cli -i x.mmd -o x.svg -b transparent` 渲染，再把 SVG 内联进 HTML。
- 颜色只做强调，不承载分类；黑白打印后仍要能靠文字和线型读懂。
- 节点文字 ≥9pt；标签横向排列，避免竖排和旋转。

详细图形选择与 SVG 约定见 `references/diagram-playbook.md`；压缩动作的前后对照见 `references/compression-rules.md`。

## HTML 规范

以 `assets/onepager.html` 为骨架，必须满足：

- 单文件、UTF-8、内联 CSS；除系统字体外无外部依赖。
- `@page { size: A4; margin: 0 }`；每个 `.page` 固定 A4，页与页之间 `break-after: page`。
- 正文 10pt / 行高 1.55；最小 9pt；标题 17pt / 11.5pt。
- 打印保留背景色：`print-color-adjust: exact`。
- 卡片、图、表加 `break-inside: avoid`；标题加 `break-after: avoid`，防止标题孤行。
- 时效区块 `.freshness`（9pt、左侧竖线、`break-inside: avoid`）放 footer 之前；附录页用 `page--freshness` 类复用 `.page`。样式已内置，格式契约见 `references/freshness-rules.md`。
- 不用 `position: fixed`、`vh`、`<details>`、hover 才能看到的内容。
- 屏幕预览显示灰底和页影；`@media print` 下去掉。
- 页脚放来源与页码（静态文本，不用 JS）；**页脚可选**：正文已完整落页、仅页脚轻微溢出时删除页脚，不升页、不缩字号、不删正文。

## 自检清单

- [ ] 页数 = 1 或 2，`.page` 数量正确。
- [ ] 每页中文字符在预算内（`check_onepager.py`）。
- [ ] 一句话答案 ≤40 字，且是完整句子。
- [ ] 每条要点 ≤25 字，删掉连接词。
- [ ] 每个数字或结论都能在原文找到依据；不确定的标"待核实"。
- [ ] 图 ≤8 或 ≤12 节点，黑白可读，无外部依赖。
- [ ] 最小字号 ≥9pt，无标题孤行。
- [ ] 页脚：可见；若仅页脚轻微溢出，已删除页脚并在报告注明「页脚省略」。
- [ ] 归属：每块首句回答本节问题；定义/定位在开头，不在流程/评测/迭代节。
- [ ] 命名：只看标题能说出任意两节区别；两个标题不共享未限定关键词（checker 会 WARN）。
- [ ] 回放测试：盖住原文只读成品，能把源文骨架完整讲一遍（同级枚举不缺项、决策链不断链）；做不到＝删过头，回退重选。
- [ ] 断言完整：保留要点均为"结论＋条件/机制"完整句，无关键词堆叠。
- [ ] 同级对称：同级枚举要么等深度全保留，要么整组合并并已在报告说明。
- [ ] 页数档位由高分 KU 数驱动；KU 清单已落地到 `.skill-state/`。
- [ ] 输出文件名使用中文（`浓缩-<中文主题>.html`），无英文 slug、拼音或日期缩写。
- [ ] 版本敏感断言已过时效校验；正文不含已被新版本推翻的结论——[演进] 条目的当前行为已写入正文，区块只承载演进脉络。
- [ ] 时效区块首行含"截至 <产品> <版本> · <日期> 核实"；每条带出处。
- [ ] 视觉验收：模型支持图像输入时做过渲染页人工过目；**不支持时已放弃读图重试，并在报告提醒用户自行过目**。
- [ ] 浏览器 Ctrl+P 预览：无空白页、无截断、无内容溢出。
- [ ] 因预算删掉但可能被追问的内容，补进第二页或明确告知用户。

## 交付

写文件到当前目录：`浓缩-<中文主题>.html`（或用户指定路径）。文件名使用中文：主题用 2–12 个中文字概括，不用英文 slug、拼音或日期缩写；用户指定路径时以用户为准，但文件名仍建议中文。聊天里只报告：

- 页数、每页字符数、图/表数量
- 高分 KU 数量与页数档位的对应（档位由选点驱动）
- 保留的 KU 数与删除的 KU 数
- 骨架删减说明：同级枚举合并/砍项的，逐条列出（无则写"骨架完整保留"）
- 视觉验收状态：已做 / **放弃（模型不支持图像输入，建议用户打印时自行过目）**
- 时效校验结果：核实 N 条，四态分布；逐条列出 [演进]（正文已按当前版改写 + 区块记演进路径）和 [未核实]
- 因预算删除但可能重要的 1–3 条
- 是否使用了"待核实"标记

不要把整份 HTML 贴进聊天。

## 异常与兜底

| 场景 | 处理 |
|---|---|
| 源文不足 1 页 | 不硬凑，输出 1 页并说明「信息量不足以支撑 2 页」 |
| 扫描版 PDF 无文本 | 先 OCR；不可用则停止并告知，不凭空补内容 |
| 超出页数/字数预算 | 按压缩阶梯删；禁止缩小字号或压缩行距 |
| 高分 KU > 12 个 | 不硬压；停下报告，建议转 `docs-to-knowledge` 或与用户确认取舍 |
| 多文档输入 | 停止并转 `knowledge-router` / `docs-to-knowledge` |
| 校验失败或无证据 | 正文标「待核实」，报告逐条列出 |
| 正文/图表溢出 | 删卡/合并要点后重跑 check；仍溢出则升页或减图 |
| 仅页脚轻微溢出 | 正文已完整落页时删除页脚，不升页、不缩字号；报告注明「页脚省略」 |
| 模型不支持图像输入 | 放弃视觉验收，不反复重试读图/视觉代理；报告提醒「未做视觉验收，建议用户打印时自行过目」；结构验收照常执行 |
| 多来源冲突 | 以最新/最权威为准并在页脚注明；无法判断时并列 |

## 状态与权限

- 多轮状态：`.skill-state/<中文任务名>.md`，字段：输入 / KU 清单（内容+分数+去留） / 页数档位 / 已删项（含骨架删减记录） / 剩余预算。KU 清单是成稿前置 gate，不落地不许写正文。
- 高风险操作需二次确认：覆盖已有 HTML、删除文件、安装 npm 包、写到用户指定目录之外。
- 不修改原始输入文件。

## 反模式

| 不要 | 要 |
|---|---|
| 每段各压一句，结果还是三页 | 先选点，再写 |
| 用"首先/其次/总之"串联 | 直接给结论和条件 |
| 为凑页数加空话 | 加一张对比表或边界条件 |
| 先定页数再削源文结构凑条数 | 页数跟着高分 KU 数走，不够就升页 |
| 同级枚举压成标签词、砍掉第 N 项 | 等深度全保留，或整组合并并显式报告 |
| 跳过打分直接套模板 | KU 清单落地后再成稿 |
| 所有知识都画图 | 只有流程、分支、层级才画 |
| 缩小字号硬塞 | 按阶梯删内容 |
| 正文先写过时结论、靠时效区块纠正 | 正文直接写当前版本，区块记演进 |
| 依赖 Mermaid CDN | 内联 SVG |
| 把内容折叠进 `<details>` | 打印时会被丢掉 |
