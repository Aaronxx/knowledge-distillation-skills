# 图谱构建规则

## 1. 节点类型

| 类型 | 识别特征 | 例子 |
|---|---|---|
| 模块/组件 | 独立部署、有名字的系统部件 | 壳(前端)、脑(Bridge)、CRM |
| 机制/流程 | 模块内的处理链路 | 意图漏斗、混合检索、飞轮 |
| 决策 | 带"为什么"的选型或取舍 | 为什么自建不用框架 |
| 细节/坑 | 接缝处的问题 + 正确做法 | 换模型必须重标定阈值 |
| 数字事实 | 可校验的量 | 三层漏斗、top-3、RRF |
| 待办/待确认 | 文档自己承认没落定 | 效果数字待补 |

## 2. 边类型

| 边 | 含义 | 落点 |
|---|---|---|
| 包含 | 模块 → 机制 | 总览主图 |
| 依赖 | 机制 → 机制（数据/调用） | 总览主图、子图 |
| 藏坑 | 机制 → 细节 | 主题页的卡片归属 |
| 关联 | 细节 ↔ 细节（同一根因、同一前提） | 交叉索引表 |
| 约束 | 决策 → 机制/细节 | 决策条目的"影响"列 |

## 3. 构建步骤

1. **逐文件抽取**：每个文档产出一张"实体表"（实体、类型、所在文件、一句话）。
2. **跨文件合并**：同名/同义实体合并（保留信息最全的一句话作代表）；一个细节被两个文档描述时，合并为一个节点、来源记两个文件。
3. **连边**：从原文找依据，不猜关系；原文有"关联"小节直接采纳。
4. **聚类**：优先采用细节集自带索引的分组；无索引时按"模块 → 接缝"聚类。
5. **成图**：层级树（markmap 输入）+ 文档内子图（SVG）+ 邻接表（交叉索引页）。

## 4. markmap 输入格式

```markdown
# <项目名> 知识图谱
## <模块 1>
### <机制 1.1>
- 细节：xxx（⭐⭐⭐）
- 细节：yyy
### <机制 1.2>
## <模块 2>
...
```

- 层级深度 ≤4，节点总数 ≤80。
- 细节行带优先级星标（若索引有），方便在图上一眼看到高优。
- 待确认项加 `[待确认]` 前缀。

生成命令（必须 --offline）：

```bash
npx -y markmap-cli --offline --no-open -o knowledge-map-<slug>.html map-src.md
```

产物自检：`grep -c 'src="http' knowledge-map-<slug>.html` 必须为 0（xmlns 命名空间不算）。

## 5. 文档内 SVG 子图

- 主图（总览页）：模块为节点、依赖为边，≤15 节点，横向分层。
- 子图（主题页）：该组机制的关键链路，≤10 节点。
- 手写 SVG 骨架与样式约定见 `distill-onepager/references/diagram-playbook.md`（字体 ≥9pt、黑白可读、无外部依赖）。
- 图的 `aria-label` 必须写明"这张图回答什么问题"。

## 6. 交叉索引表（图谱的打印形态）

| 细节 | 所在机制 | 关联细节 | 优先 |
|---|---|---|---|

- 每个细节文件一行，"关联细节"填编号（来自原文关联小节或同根因）。
- 这张表就是图谱的邻接表：屏幕上看 markmap，纸上查这张表。
