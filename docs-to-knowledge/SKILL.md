# 多文档 → 结构化知识 + 知识图谱

## 解决什么问题

一个项目的知识往往散落在多个文档里：一份总纲讲整体，一叠细节文件讲接缝处的坑。本 skill 把它们聚合为两样产物：

1. **`knowledge-<slug>.html`**：3–6 页 A4、零 JS、可打印的结构化知识文档。按"总览 → 主题 → 交叉索引"组织，图谱关系以图和表落在页面里。
2. **`knowledge-map-<slug>.html`**：markmap 生成的自包含交互图谱（缩放/折叠），供屏幕上浏览全貌。

与 `distill-onepager` 的分工：那是个"压缩器"（1–2 页硬预算），本 skill 是"结构化整理器"——**页数由内容定，只设上限不设目标**；关键说明（话术、数字、配置、诚实校准）必须保留。两者共享打印契约与时效区块格式（`distill-onepager/references/freshness-rules.md`）。

## 边界清单

| 能做 | 不做 |
|---|---|
| 多文档/目录 → 3–6 页结构化知识 HTML + markmap 图谱 | 1–2 页硬压缩（→ `distill-onepager`） |
| 单文档 >8000 字，或 >3000 字且 H2 ≥5 | 版本判定本身（→ `fact-freshness-check`） |
| 保留话术/数字/诚实标记；交叉索引邻接表 | 在线 wiki/数据库/Neo4j；超过 6 页；交互式编辑 |
| 图谱树 + 打印版邻接表 | 非文本输入；纯代码仓库 |

## 输入约定

- 至少一个**入口文档**（总纲、README、索引）+ 一个或多个**细节文档**（目录或散文件）。
- 细节集若自带索引（分组/优先级/一句话），以它为聚类先验，但要用原文核验——索引可能过时。
- 支持格式：Markdown、TXT。DOCX/PDF 先转文本（有 documents/pdf skill 时用它们）。

## 路由元信息

| 项 | 内容 |
|---|---|
| 正向触发 | 知识图谱、多文档聚合、整理成知识、结构化知识、项目知识库、保留细节 |

## 工作流

1. **清点**：读入口文档 + 目录递归收集所有文档；记录每个文档的主题一句话与相互引用。入口缺失时先向用户确认哪个是总纲。
2. **实体提取**：从每个文档提取实体——模块/组件、机制/流程、决策（含 why）、细节/坑、Trade-off、数字事实。细节文档常自带固定小节（如"现象/做法/话术"），按小节拆，不按段落拆。
3. **图谱构建**：按 `references/graph-rules.md` 定义节点与边；合并跨文件重复实体；输出图谱源（markdown 层级树给 markmap，子图 SVG 给文档内嵌）。
4. **页面规划**：按图谱聚类分配页面——第 1 页总览，中间每页一个模块或接缝组，末页交叉索引与遗留清单。细节按优先级排序，同页放不下的挪后页，不许丢。
5. **编辑契约（强制）**：为总览页、每个主题页、附录页填「页面契约 + 术语表」，跑 MECE 测试；写完后做冷读者复审。详见 `distill-onepager/references/editorial-qa.md`。
6. **成稿**：按"保留规则"取舍；每条细节压缩成 2–4 行卡片，但关键说明原样保留。
7. **图谱渲染**：跑 markmap-cli 生成交互图谱；文档内嵌图手写 SVG（`distill-onepager/references/diagram-playbook.md` 的骨架）。
8. **时效校验（必选，用户明确说"不用校验"才跳过；由 knowledge-router 调用时同样强制）**：版本敏感断言按 `fact-freshness-check` 处理，正文只写当前版本事实；输入为项目自述且无外部技术断言时，报告写明"无版本敏感断言，未联网校验"。
9. **自检**：跑 `python scripts/check_knowledge.py <file.html> [--map map.html]`，再过人工清单，最后做冷读者复审。

## 编辑契约（防错位/撞车）

多文档最容易出现两类问题：总纲的定义被塞进某个主题页；不同细节组的标题共享同一个抽象词（如都含“一致性/同步”）。

写页面之前填两张表：

1. **页面契约**：页面 / 这一页回答的问题 / 只收 / 不收。总览页只放定义、模块分工、核心决策；主题页只放该模块的机制与细节；附录只放出处、演进、待办。
2. **术语表**：模块名 / 管什么 / 不管什么 / 易混。两个主题页标题共享未限定关键词 → 加限定词或合并。

**MECE 测试**：同一张细节卡能否同时放进两个主题页？能 → 页面边界没写清。

写完后做**冷读者复审**：只读页面标题和每张卡首句，回答“这张卡在回答本页的问题吗”“只看标题能分清这两页吗”。清单不为空就返回修改。完整规则见 `distill-onepager/references/editorial-qa.md`。

## 保留规则（本 skill 的灵魂）

**必须保留**（这是"不要求最大压缩"的含义）：

- 数字与事实：阈值、版本号、量化结论、配置项。
- 关键说明：结论性话术、设计 why（"为什么这么做"的一两句原文）。
- 诚实标记：待确认/待补/如果当时没做过的降级口径——它们是可信度，删了就是造假。
- 坑的复现条件与错误现象（"没有报错，只会表现为未命中率慢慢升高"这类）。

**必须删**：

- 跨文件重复的背景铺垫（N 个文件都在讲同一个系统是什么，总纲页讲一次就够）。
- 与主题无关的展开、引用来源的客套话、同一文档内部的自重复。

**压缩手法**：叙述改条目、条目改卡片；一段流程压成一行"步骤链 A→B→C"；但每条至多压到 2 行，再往下就丢关键说明了。

## 页面预算

| 页 | 职责 | CJK 上限 |
|---|---|---|
| 第 1 页 | 系统总览：一图（主架构）+ 模块分工表 + 核心决策 3–5 条 | ≤900 |
| 主题页 ×2–4 | 每页一个模块/接缝组：机制要点 + 该组细节卡片 + 子图 | ≤950/页 |
| 末页 | 细节交叉索引表（图谱邻接表）+ 待确认/待补清单 | ≤700 |

总字符 = 各页之和，一般 3000–4500。**超上限按保留规则删铺垫，不删关键说明；页数顶到 6 还装不下，说明要拆主题，回来重排页面。**

## 图谱方案（开源工具）

| 工具 | 用途 | 状态 |
|---|---|---|
| `markmap-cli` | 层级知识图谱，自包含交互 HTML | **主引擎**，`npx -y markmap-cli --offline --no-open -o <out>.html <src>.md` |
| 手写内联 SVG | 文档内的机制子图（打印友好） | 默认，骨架见 diagram-playbook |
| `@mermaid-js/mermaid-cli` | 从 mermaid 源渲染 SVG | 可选增强；首次运行要下载 Chromium（约 2 分钟），可用 `-p puppeteer.json` 指向系统 Chrome `{"executablePath":"..."}`；失败就退回手写 SVG |

不引入 GraphRAG/Neo4j/LLM Graph Transformer：图规模 <100 节点、产物是静态文档，杀鸡不用牛刀。

markmap 输入是层级 markdown——`#` 根 → `##` 模块 → `###` 机制 → 列表项细节；**markmap 只能表达树，没有边**，所以交叉引用（细节 A 关联细节 B）写在文档的交叉索引页，图谱页不硬画。

## 异常与兜底

| 场景 | 处理 |
|---|---|
| 入口文档缺失 | 先确认哪个是总纲，不猜 |
| 索引与原文冲突 | 以原文为准，报告差异 |
| 超过 6 页 | 拆主题或转 `distill-onepager`，不缩字号 |
| markmap 失败/含外部资源 | 退回层级表 + 邻接表，报告 |
| 扫描版 PDF 无文本 | 先 OCR；不可用则停止 |
| 细节文件未覆盖 | 补齐落点，或说明排除理由 |

## 状态与权限

- 多轮状态：`.skill-state/<task-slug>.md`，字段：输入清单 / 实体表 / 页面分配 / 已覆盖文件 / 待确认。
- 高风险操作需二次确认：覆盖已有产物、删除中间文件、安装 npm 包/联网、写到指定目录之外。
- 不修改原始文档。

## 自检清单

- [ ] 页数 3–6，每页字符在上限内（check_knowledge.py）。
- [ ] 入口文档的每个模块在文档里都有落点；细节目录的每个文件都被引用至少一次（逐文件核对，防漏收）。
- [ ] 诚实标记原样保留且醒目（待确认/待补/设计扩展）。
- [ ] 归属：每个主题页只回答页标题的问题；定义与总览不散落在细节页。
- [ ] 命名：任意两个主题页标题能分清；无共享未限定关键词（checker 会 WARN）。
- [ ] 图：主图 ≤15 节点、子图 ≤10；节点文字 ≥9pt。
- [ ] markmap 产物无 CDN 依赖（`grep -c 'src="http' map.html` 为 0）。
- [ ] 交叉索引表能回答"细节 X 影响哪些环节"。
- [ ] 浏览器 Ctrl+P 预览无截断、无空白页。

## 交付

写 `knowledge-<slug>.html` 与 `knowledge-map-<slug>.html` 到当前目录（或用户指定路径）。聊天里报告：页数、各页字符数、收录文档数/细节条数、图谱节点数、保留了哪些关键说明类别、待确认清单条数。不要把 HTML 全文贴进聊天。

## 反模式

| 不要 | 要 |
|---|---|
| 按 distill-onepager 的 1–2 页硬压 | 页数由内容定，上限 6 |
| 删掉"诚实校准/待确认"让文档更干净 | 原样保留，它们是可信度 |
| 为了图谱好看硬把交叉关系塞进树里 | 树归 markmap，交叉引用归索引表 |
| 只读索引不读原文（索引会过时） | 索引当先验，原文为准 |
| 每页塞满 950 字 | 上限是防爆线，不是目标 |
| markmap 输出直接交给用户不检查 | 必须 grep 确认无 CDN、可离线打开 |
